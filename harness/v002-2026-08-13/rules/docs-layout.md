# 문서를 쓰는 자리

| 어디 | 무엇 | 수명 |
|---|---|---|
| docs repo `projects/PRO-N-슬러그/spec/APP-N/spec.md` | 이슈 설계 (spec) | **이 레포에 두지 않습니다** |
| `docs/superpowers/plans/` | writing-plans 산출물 (계획) | 작업과 함께 굳습니다 |
| `DESIGN.md` | 디자인 판단의 원본 | 코드가 바뀌면 같이 고칩니다 |

spec은 PRD와 같은 자리에 삽니다 — docs repo의 `projects/`가 프로젝트(PRD) 아래 이슈별 spec을
답니다. **spec은 이 레포의 판단이 아닙니다** — 구현 착수 전에 쓰이고 팀 리뷰를 거친 그
문서가 이 작업의 입력입니다. 이 레포에는 구현 계획만 남습니다.

## plan을 언제 쓰나

**plan은 없어도 됩니다.** 여러 파일에 걸쳐 **순서가 중요할 때**만 씁니다. 파일 하나 안에서
끝나는 작업에 plan을 쓰지 않습니다.

**`plans/`의 파일명은 `YYYY-MM-DD-APP-N-이슈제목.md`입니다.**

```
2026-07-26-APP-205-인증-만료-시-token-refresh-무한-루프-세션-게이트-전역-재시도-정책.md
```

- 날짜는 문서를 쓴 날, `APP`은 대문자, 제목은 **Linear 이슈 제목 그대로**입니다
- 제목은 Linear가 이슈 URL에 쓰는 슬러그를 그대로 씁니다 — 공백은 하이픈, 특수문자는 제거,
  영문은 소문자입니다. 직접 줄여 쓰지 않습니다
- **이슈 번호를 빼지 않습니다.** 빼면 이 문서가 어느 작업의 산출물인지 git log를 뒤져야
  압니다. 실제로 초기 문서 20건이 번호 없이 쌓였고, 되짚을 수 없어 지웠습니다
- 번호를 못 붙일 문서면 plan을 쓸 자리가 아닙니다

**writing-plans skill의 기본 파일명(`YYYY-MM-DD-<feature-name>.md`)에는 번호가 없습니다.**
그대로 두면 또 번호 없는 문서가 쌓입니다. 위 형식으로 고쳐 저장하세요.

heymoa-ai의 `docs/issues/APP-N-slug/`로 통일하지 않았습니다 — 옮기면 마이그레이션만 생깁니다.

## 어디에 안 넣나

- 계약 원본을 `docs/`에 복사하지 않습니다. 원본은 docs repo(`../docs`)의 `origin/main`이고
  진입점은 그 레포의 `INDEX.md`입니다.
- 토큰 값·파일 목록처럼 코드가 원본인 것을 문서에 옮기지 않습니다. 기준만 쓰고 원본을 링크합니다.
- 하네스 안(`harness/`)에 설계 문서를 쓰지 않습니다. 하네스는 지시이고 설계는 docs repo입니다.
