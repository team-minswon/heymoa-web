# 확인 창, 줄바꿈, 정렬

사용자가 같은 말을 여러 번 했던 자리입니다. 값(색·간격·글꼴)은 [`DESIGN.md`](../../../DESIGN.md)와
`app/globals.css`가 원본이라 여기 적지 않습니다. 여기는 기준과 확인 방법만 둡니다.

## 기준 폭은 데스크톱입니다

1440과 1024로 그리고 확인합니다. 390px 레이아웃·캡처·검사를 새로 만들지 않습니다. 지금 제품은
데스크톱에서 쓰입니다. 이미 모바일을 지키던 곳(랜딩·처리방침)은 깨지지만 않게 두고, 가로 스크롤이
새로 생기는 회귀는 만들지 않습니다.

## 확인·경고는 모달로 띄웁니다

되돌리기 어려운 행동(초기화, 삭제, 내보내기, 권한 회수)의 확인과 경고 문구는 화면에 상시 두지 않고,
누른 순간 `components/ui/alert-dialog.tsx`(shadcn `AlertDialog`)로 띄웁니다. 「알림 설정 기본으로
돌리기」 같은 버튼 옆 경고 문단이 그 예입니다. 화면에 늘 있는 경고는 읽히지 않고 자리만 차지합니다.

- `window.confirm`·`alert`를 쓰지 않습니다. 브라우저 기본 창은 문구·버튼을 못 맞추고 테스트에서 막힙니다
- 새 확인 창을 직접 만들지 않습니다. 이미 쓰는 곳(`members-settings`, `rename-person-dialog` 등)을 보고 같은 꼴로 씁니다
- 버튼 순서와 정렬은 `AlertDialogFooter`가 정한 대로 둡니다(취소 → 실행, 오른쪽 정렬). 클래스로 덮어 바꾸지 않습니다
- 「지금 할 수 없음」처럼 지속되는 상태는 모달이 아니라 인라인 `Alert`입니다. 기준은 [`error-loading`](error-loading.md)

## 한국어 줄바꿈

전역 `body`의 `word-break: keep-all`(`app/globals.css`)이 낱말 단위로 줄을 바꿉니다. 컴포넌트마다
`break-keep`을 다시 붙이지 않습니다. 그 위에서 아래를 확인합니다.

| 무엇 | 어떻게 |
|---|---|
| 날짜·시각(`10월 22일 오후 3:00`), 회의 제목 한 덩어리, 버튼·칩 문구 | 중간에서 갈리면 안 됩니다. `whitespace-nowrap`, 넘치면 `truncate` |
| 제목·모달 제목 | `text-balance` — 마지막 줄에 한 낱말만 남지 않게 |
| 본문 마지막 줄 | 조사·어미 한 덩어리(「을」, 「합니다」)만 떨어지지 않았는지 봅니다. 문장을 고치거나 폭을 봅니다 |

문구를 쓰거나 고쳤으면 **그 글이 실제 폭에서 몇 줄로 어디서 꺾이는지** 1440과 1024로 렌더해 봅니다.
jsdom은 줄바꿈을 못 봅니다.

## 정렬과 배치

새 화면이나 모달은 옆의 기존 컴포넌트와 같은 리듬이어야 합니다 — 버튼 순서, 왼쪽 기준선, 위아래 간격,
아이콘과 글자의 세로 중심. 눈으로 「맞아 보인다」로 끝내지 않고 `getBoundingClientRect()`로 숫자를
비교합니다(같은 열의 `left`가 같은지, 반복 간격이 같은지). 어긋남은 대개 1~4px이라 캡처로는 안 보입니다.
