# 이 레포의 코드 리뷰 방법

`codex exec review`와 리뷰 subagent 전부가 이 방법을 씁니다. 무엇을 어디까지 볼지는 부르는
쪽이 정하고, 이 문서는 **무엇을 어떤 라벨로 어떻게 적는지**만 정합니다.

지적 형식(무엇·어떻게·왜)과 태도는 [`AGENTS.md`](../../../../AGENTS.md)가 원본입니다.
여기 다시 적지 않습니다.

## 심각도와 위험도

심각도는 "맞다면 얼마나 나쁜가"이고, 위험도는 "얼마나 확실하고 얼마나 번지는가"입니다.
둘은 다른 것이라 따로 답니다. 확신 없는 P1이 확실한 P2보다 먼저 고쳐질 이유는 없습니다.

| 심각도 | 뜻 | 머지 게이트 |
|---|---|---|
| `P1` | 지금 당장입니다. 데이터 손실·인증 파손·계약 파괴처럼 번지는 것 | 막습니다 |
| `P2` | 고쳐야 합니다. 국소 오동작·규약 위반·유지보수 손상 | 막습니다 |
| `P3` | 개선 제안입니다 | 안 막습니다 |

P1과 P2는 **둘 다 머지를 막습니다.** 가르는 것은 급한 정도이지 막느냐 아니냐가 아니므로,
애매하면 P2로 두세요. 호스트(codex 등)가 자기 우선순위 척도를 쓰면 **그쪽을 따르고**
지적 본문에 이 라벨을 적습니다 — 게이트 판정에 필요한 것은 라벨이 본문에 남는 것뿐입니다.

P3는 아끼지 마세요. 머지를 안 막으니 편하게 적되, 등급을 올려 P2로 적지는 마세요.
등급을 올려야 말할 수 있게 되면 리뷰가 왜곡됩니다.

| 위험도 | 뜻 | 처리 |
|---|---|---|
| `blast` | 인증·계약·전역 캐시까지 번집니다 | 무조건 고칩니다 |
| `blocking` | 그 기능이 실제로 안 됩니다 | 고칩니다 |
| `local` | 국소적이고 되돌리기 쉽습니다 | 고치거나, 근거를 적고 반려합니다 |
| `speculative` | 재현 경로를 못 짚었습니다 (추정) | 반려해도 됩니다. 사유를 적습니다 |

`speculative`를 확신처럼 쓰지 마세요. 없는 함정을 피하는 구조가 남고 그건 되돌리기 비쌉니다.

## 먼저 보는 되풀이된 결함

`docs/codex-review-app-*.md`에서 **실제로 다시 나타난 것들**입니다. 순서대로 훑으세요.

| 렌즈 | 어떻게 나타났나 |
|---|---|
| **실패를 빈 상태로 접기** | 조회 실패와 "데이터 없음"을 같은 화면으로 그립니다. 사용자는 비어 있다고 믿습니다 (`note-archive`·공유 챗 히스토리·활성 세션 조회) |
| **stale 캐시** | 남이 바꾼 상태가 안 따라옵니다. mutation 뒤 invalidate 대상이 좁거나 `void`로 흘려 보냅니다 (요약 탭·다중 멤버 회의·연동 설정) |
| **오류가 두 번 뜹니다** | 인라인으로 그려놓고 전역 토스트를 opt-out하지 않았습니다. 전역 훅이 호출부 `catch`보다 먼저 돕니다 |
| **경계 상태가 안 풀립니다** | 리소스를 떠나거나 겹쳐 조작해도 이전 상태가 남습니다. 죽은 카드가 늦은 이벤트로 되살아납니다 (`resetKeys` 누락 계열) |
| **긴 목록이 안 따라갑니다** | 새 출력이 화면 밖에 쌓입니다. 스크롤 의도를 DOM 추가 전에 보존하지 않았습니다 |
| **목이 제품과 갈립니다** | MSW 핸들러가 실제 계약과 다른 응답을 줘서 화면은 되는데 실제로는 안 됩니다 |

## 전부 한 번에 내기

가장 중요한 것만 골라 보고하지 마세요. 한 건씩 내면 고치고 다시 도는 왕복이 그만큼 늘어납니다.

`P1` → `P2` → `P3` 순으로 전부 나열하고, 같은 등급 안에서는 위험도 순으로 놓습니다.

`harness/`의 rule과 skill은 에이전트에게 주는 실행 지시입니다. 코드 버그를 찾지 말고 지시가
일관되고 실행 가능한지를 보세요. 특히 **두 문서가 같은 규칙을 다르게 말하는 자리**와
**코드가 원본인 값을 문서가 복사한 자리**를 봅니다.

## 지적 하나를 적는 형식

```
[P1][blast] 한 줄 요약 — path/to/file.tsx:120-124
무엇: 무엇이 잘못됐나
어떻게: 어떤 입력·상태에서 터지나 (구체적으로)
왜: 코드의 어느 줄이 원인인가
```

**호스트가 정하는 출력 껍데기는 건드리지 않습니다.** `codex exec review`는 자기 리뷰
스키마로 결과를 냅니다 — 위 형식은 그 안의 **지적 본문**을 쓰는 방법이고, 응답 전체를
마크다운으로 바꾸라는 뜻이 아닙니다. 스키마가 없는 리뷰 subagent만 위 블록을 그대로 씁니다.

`- P1·P2 없음` 같은 결과 줄은 쓰지 않습니다. 이 레포에는 그 줄을 읽는 파서가 없습니다
(heymoa-ai에는 `land.py`가 있어서 필요합니다). 머지 판단은 사람이 P1·P2 유무로 합니다.

## 회차

P1·P2를 고치고 다시 돌립니다. 회차 기록이 필요하면 `docs/codex-review-app-N.md`에 남깁니다.
이 레포에서 한 브랜치가 6회차까지 간 적이 있습니다(`docs/codex-review-app-110.md`).
