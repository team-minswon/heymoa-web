**1** — `autoOpen` 이 `sharedTurnActive` 를 안 봤다. 답변이 흐르는 중에 다른 멤버가 회의를

채로 가려진다.** 스트림은 살아 있는데 화면에서만 사라지는 것이라 언마운트보다 알아채기 어렵다.
→ 턴이 도는 동안은 안 편다.

**2·3** — `autoOpen` 을 `setScopeNoteId` **뒤로** 옮기고, 노트를 떠날 때 되접게 했다.
`autoOpenedNoteRef` 는 「자동으로 연 것인가」의 표식이 되어 4도 같이 닫혔다 — 사용자가 연 것은
안 접는다.

회귀 테스트 둘을 달았다 (`personal-chat.test.tsx`) — 「노트를 떠날 때 되접힌다」와
「사용자가 연 것은 안 접는다」.

## 고친 것 — 브랜치에 이미 있던 것

| # | 심각도 | 무엇 | 어디 |
|---|---|---|---|
| 7 | P2 | blur 자동 저장이 겹쳐 응답 역순이면 옛 값이 최종값이 됐다 | `workspace-settings-form.tsx` |
| 8 | P2 | 검증 실패를 화면에 안 적어 저장된 줄 알았다 | 같은 파일 |

**7** — 이름을 고치고 설명으로 옮기면 PATCH 가 뜨고, 설명까지 고치면 두 번째가 뜬다.
둘 다 폼 전체를 보내므로 응답이 역순으로 오면 먼저 보낸 옛 값이 이긴다.
→ `saveChainRef` 로 직렬화했다. 부수 효과로 두 입력이 한 요청으로 합쳐진다.

**8** — `handleSubmit` 은 값이 유효하지 않으면 조용히 아무것도 안 보내는데, 화면은
「변경은 바로 저장됩니다」라고 말한다. → `FieldError` 로 그 자리에 이유를 적는다.

두 테스트를 달았고 **둘 다 변이 테스트로 이빨을 확인했다** — 고친 코드를 되돌리면 빨개진다.
직렬화 테스트는 처음에 태그 기반으로 썼다가 **고장 난 코드에서도 통과**해서 다시 썼다.
지금은 겹침 여부(`start·end` 교대)라는 불변식 자체를 잰다.

## 안 고친 것

**[P2] 다른 워크스페이스의 회의 알림이 잘못된 주소로 간다** — `lib/notifications/describe.ts:59`.
알림은 유저 전역인데 계약의 `note` 에 `workspaceId` 가 없어서 목적지를 **지금 보고 있는
워크스페이스**로 조립한다. 워크스페이스 B 의 알림을 A 에서 누르면 403/404 로 떨어진다.

codex 는 「계약이 보완되기 전에는 그 액션을 제공하면 안 된다」고 했다. 타당하지만 그러면
알림 다섯 종 중 넷이 눌리지 않는 항목이 된다 — **제품 판단이라 임의로 정하지 않았다.**
계약 구멍은 `design/CONTRACT-BACKLOG.md` 에 있고, 필드가 실리면 이 파일 한 곳만 고치면 된다.
