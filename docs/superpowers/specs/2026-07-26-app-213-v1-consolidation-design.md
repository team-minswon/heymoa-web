## 2-3. 예외 상황의 도달 가능성

**목으로 밟을 수 있는 것과 없는 것을 갈라 둔다.** 못 밟는 것을 "확인했다"고 적으면 그게 다음
감사를 속인다.

| 예외                        | 도달 | 방법                                               |
| --------------------------- | ---- | -------------------------------------------------- |
| 빈 노트 목록                | ✅   | 새 워크스페이스를 만든다                           |
| 분석 진행 중 스켈레톤       | ✅   | 회의 종료 직후                                     |
| 회의 종료 상태              | ✅   | 회의 종료                                          |
| 알림 빈 상태 · 읽음         | ❌   | 시드에 알림이 항상 있다                            |
| 주 데이터 404 · 분석 FAILED | ❌   | 목 핸들러가 성공만 준다                            |
| 스트림이 종료 없이 끊김     | ❌   | SSE 목이 정상 종료만 한다                          |
| 관전자 · 남의 잠금          | ❌   | `seedForeignLock`이 테스트 전용이고 UI 경로가 없다 |
| 비ADMIN · 만료된 초대       | ❌   | 목 유저가 항상 ADMIN이다                           |
| 인증 만료(세션 게이트)      | ❌   | 목이 항상 인증돼 있다                              |

**도달 못 하는 것은 컴포넌트 코드와 테스트를 근거로 그린다.** 그 사실을 프레임 노트에 적어,
다음 사람이 "실측된 화면"과 "코드로 그린 화면"을 구분할 수 있게 한다.

## 2-4. 드리프트 — 프리미티브 기본값이 스케일 밖이다

**제품 면 오버레이는 e3 2연타 + panel 16이어야 하는데(ELEVATION SPEC), 다이얼로그 셋과
드롭다운 하나가 radius 22.4에 그림자가 없다.**

원인은 표면이 아니라 프리미티브다.

| 프리미티브             | 기본 radius             | 스케일  |
| ---------------------- | ----------------------- | ------- |
| `ui/dialog.tsx`        | `rounded-xl` = **22.4** | 밖      |
| `ui/alert-dialog.tsx`  | `rounded-xl` = **22.4** | 밖      |
| `ui/card.tsx`          | `rounded-xl` = **22.4** | 밖      |
| `ui/dropdown-menu.tsx` | `rounded-lg` = 16       | panel ✓ |

APP-209·211은 **표면별로** 고쳤다(설정 다이얼로그·시트·챗 카드·알림 드롭다운). 그래서 호출부가
값을 명시한 곳만 맞고 기본값을 쓰는 곳은 그대로다.

**이건 APP-210(형태 스케일 일원화)에서 고칠 것이고 여기서 고치지 않는다.** 이 이슈는 실측과
캔버스이고, 프리미티브를 건드리면 90곳이 함께 움직여 감사와 수정이 뒤섞인다.

> **2026-07-27 — 둘 다 끝났다.**
> radius는 APP-210, 그림자는 APP-222다. 프리미티브 기본값이 각각 `rounded-panel`과
> `shadow-e3`가 됐고, 호출부에 중복으로 박혀 있던 `border`도 걷어 외곽선을 ring 하나로 모았다.
> **그래서 위 2장의 첫 실측값은 낡았다** — 재실측값이 정본이다.
>
> APP-210에서 하나 더 나왔다. `cn()`이 커스텀 radius를 tailwind-merge 충돌 그룹으로 보지
> 않아 `rounded-panel rounded-none`이 둘 다 살아남고 CSS 선언 순서가 이겼다. 프레임을
> 그릴 때 "호출부가 명시했으니 그 값이겠지"를 믿으면 안 되는 이유다 — 반드시 실측한다.

## 3. 판정 — 규칙이 갈리는 곳

**마케팅·인증 면은 제품 면 규칙 대상이 아니다.** FORM SPEC의 대문자 키커 금지와 ELEVATION SPEC의
e2/e3 2연타는 제품 화면에 한정된다(SPEC 본문이 "제품 면", "마케팅(랜딩·약관) 전용"이라고 갈라 둔다).

따라서 아래는 **드리프트가 아니다.**

| 무엇                                     | 값           | 이유      |
| ---------------------------------------- | ------------ | --------- |
| 인증 모달 radius 28.8 · 단일 티어 그림자 | 스케일 밖    | 인증 면   |
| 404의 `ERROR 404` 키커                   | 대문자       | 마케팅 셸 |
| 랜딩 카드의 단일 티어 그림자             | `0 4px 16px` | 마케팅 면 |

**`/mock-oauth`는 캔버스에 넣지 않는다.** 목 전용 화면이라 제품이 아니다.

## 4. 방법 — fullPage 캡처를 믿지 않는다

랜딩을 `fullPage`로 찍었더니 카드 3장 섹션이 **통째로 비어 나왔다.** DOM은 opacity 1이었고
뷰포트 단위로 다시 찍으니 정상이었다. 스티칭 문제다.

그대로 믿었으면 "랜딩에 340px 빈 띠" 라는 **없는 결함**을 이슈로 만들 뻔했다.
→ 이 감사는 **뷰포트 단위 캡처 + `getComputedStyle` 실측**을 함께 쓴다.

### 새로 찾은 드리프트

다이얼로그 footer가 `rounded-b-xl`이라 아래 두 모서리만 22.4다. 패널은 APP-210이 16으로
맞췄는데 footer 호출부는 그대로였다. 프레임에도 실제 그대로 그렸다.

### 캔버스 작업에서 걸린 것

- `batch_design`의 인자 이름은 `input`이다(`snippet` 아님). `filePath`는 필수다
- 프레임 높이를 고정값으로 두면 내용보다 커서 빈 공간이 남는다 → `fit_content`
- `snapshot_layout`은 `nodeId`를 줘도 **캔버스 전체**를 돌려준다. 프레임 확인은
  `get_screenshot`으로 한다
- `note` 노드는 `fill`을 안 받는다. 최상위에만 둔다
- **렌더러가 한동안 새 자식 노드를 안 그렸다.** 프레임 자신과 최상위 도형은 나오는데
  새로 만든 자식만 빈 이미지였다. 같은 시기에 `batch_get`도 엉뚱한 서브트리를 돌려줬다.
  Pencil 재시작 뒤 `batch_get`이 먼저 정상화됐고 렌더러는 그보다 늦게 돌아왔다.
  → **막히면 `batch_get`으로 데이터를 먼저 확인한다.** 문서가 맞는데 그림만 안 나오는
  경우가 있다. 확인 못 한 채로 그리지는 말 것
- `export_nodes`는 큰 프레임을 여러 개 한 번에 넘기면 타임아웃난다(부분 출력 없음).
  1440×900은 1~2개씩, 아주 큰 것은 `scale: 1`로 부른다

## 5-2. ③단계 완료 — 캔버스 통합 (2026-07-27)
