# APP-1548 민감정보를 가린 PostHog 세션 리플레이 도입

## 적용 순서

1. 웹 처리방침과 서비스 화면 공고를 먼저 배포합니다. 공고일 2026-11-11, 시행일 2026-11-18이며 그 전에는 녹화하지 않습니다. 실제 공고 배포가 늦어지면 공고일·시행일·녹화 gate를 함께 미룹니다. 이번 작업에서는 배포하지 않았습니다.
2. PostHog 프로젝트 659761의 녹화 허용은 이미 켜져 있고 보관은 30일입니다. 클라이언트의 차단이 원인이었습니다. 프로젝트 설정을 변경하지 않았습니다.
3. 11월 18일 이후 서버의 `CONSENT_PRIVACY_VERSION`을 `2026-11-18`로 설정합니다. `heymoa-server/src/main/resources/application.yml`은 이 환경변수를 읽으며 기본값은 `2026-10-23`입니다. 운영값은 이 작업에서 변경·조회하지 않았습니다. `ConsentProperties`의 현재버전과 `GetCurrentUserInfoService`가 동의 기록을 비교합니다.
4. 웹은 서버가 반환한 현재 PRIVACY 버전이 시행일과 같고 `agreed=true`인 사용자만 녹화합니다. 예전 버전 동의·익명·조회 실패는 녹화하지 않습니다. 따라서 두 저장소의 원자적 배포는 필요 없고, 서버만 먼저 올려도 날짜 gate가 보호합니다. 기존 로그인 세션은 강제로 동의시키지 않습니다. 다음 로그인 callback의 명시적 동의 뒤 녹화됩니다. `lib/auth/login-consent.ts`가 서버 버전을 그대로 제출합니다.
5. 시행 뒤 테스트 계정으로 전사·요약·채팅·노트 제목·폼 입력을 열어 실제 PostHog Replay 원본이 가려지는지 확인합니다. 입력·이미지·미디어·iframe·캔버스·JSON-LD·네트워크 본문과 헤더·콘솔은 제외합니다. DOM 속성까지 가리므로 리플레이의 시각적 충실도는 떨어질 수 있습니다. 텍스트 내용 대신 화면 이동과 조작 흐름을 확인하는 도입입니다.
6. 이용 통계 거부는 기존 `heymoa:analytics-opt-out`을 그대로 사용합니다. 거부 직후 recorder를 중지하고 새 `$snapshot`을 `before_send`에서 폐기합니다. 다른 탭의 거부도 반영합니다. 이미 전송 완료되었거나 네트워크로 전송 중인 요청을 소급 취소한다는 뜻은 아닙니다.

## 공고 근거

`lib/page-dates.ts`는 공고·시행 사이 7일 이상과 서버 동의 버전 동기화를 명시합니다. `messages/ko/legal.json`의 처리방침 제12조는 “시행 7일 전부터 이 페이지와 서비스 화면에 알립니다”, 중요 변경은 “변경 전후 대조표를 함께 공개합니다”라고 정합니다. 새 서비스 화면 안내와 처리방침 마지막 변경표를 같이 두었습니다. 당일 시행 예외를 새로 적용하지 않았습니다.

## 검증

- 날짜 gate 경계, 새 버전 동의 여부, 인증·데스크톱·테스트 워크스페이스 제외, 거부 즉시 중지·snapshot 폐기와 다른 탭 반영을 단위 검증합니다.
- 설치된 posthog-js 1.438.3 타입과 recorder 소스에서 로컬 masking 우선순위와 `captureCanvas.recordCanvas=false`를 확인했습니다.
- 프로덕션 브라우저에서 Replay 수신·실제 마스킹 여부는 시행 전 검증으로 주장하지 않습니다. 현재는 클라이언트 코드와 제외 규칙 검증이며 배포하지 않았습니다.
