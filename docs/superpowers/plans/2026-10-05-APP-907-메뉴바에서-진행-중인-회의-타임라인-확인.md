# APP-907 구현 계획

설계: docs `docs/app-907/meeting-popover @ 55298dc`의 PRO-55 spec/APP-907/spec.md.

1. optional desktop 표시 DTO와 웹 selector를 추가합니다. 현재 노트를 읽을 때는 기존 provider를 사용하고 다른 화면에서는 녹음 중인 노트의 provider만 유지합니다.
2. 메인 IPC에 sender·frame·origin·표시 크기 검증을 넣고, 녹음 중지·문서 교체·renderer 소실 때 내용을 삭제합니다.
3. 별도 sandbox 로컬 팝오버와 최소 preload를 연결합니다. 왼쪽 클릭은 팝오버, 오른쪽 클릭은 기존 녹음·앱 종료 메뉴를 사용합니다.
4. 유형·근거·아래 화살표·두 단계 펼침 UI를 구현하고 갱신 시 DOM과 스크롤 의도를 유지합니다.
5. 실제 renderer·IPC·삭제·위치·호환성 회귀와 기존 native/web 전체 게이트를 실행합니다. ASAR allowlist와 Mac 실제 창을 확인한 뒤 Codex 리뷰·로컬 squash merge합니다.

운영 웹 배포와 공개 앱 배포는 로컬 구현 검증과 별도로 보고합니다. Windows 실제 실행은 APP-896의 증거가 필요합니다.

## 메뉴 상태와 행동 후속

설계 후속: docs `docs/app-907/menu-state-actions @ d803976`의 같은 APP-907 spec.

- Native 메뉴와 오래된 클릭 전달, 웹 수신 경계에서 recording 상태만 stop을 허용합니다. 시작 요청을 취소하는 기능은 추가하지 않습니다.
- Native lifecycle의 phase와 unknown을 로컬 표시 DTO에 전달하여 확인 불가·시작·중지 대기를 빈 녹음과 구분합니다. 최초 대기 상태의 열기 행동은 HeyMoa 열기로 표시합니다.
- 시작 중 및 중지 후 지연 클릭 차단, 녹음 재개 시 stop 허용, 확인 불가 문구와 빈 화면 행동의 회귀를 검증합니다. 기존 종료 보호·IPC·실제 renderer 검증과 전체 게이트를 유지합니다.
- 시작 중 종료 대기는 녹음 상태에 진입한 뒤 한 번 중지를 전달하고, 종료 대기를 취소하면 후속 녹음은 건드리지 않습니다. 캡처 해제와 전송 완료를 확인하는 기존 종료 보호를 유지합니다.
