# APP-1549 웹 테스트 전수 점검과 중복·불안정 검사 정리

## 점검 범위와 순서

웹 단위·컴포넌트·브라우저 테스트 목록과 실행 설정 전체를 분류하고, 실제 실패 trace를 대기·환경·검사 중복별로 대조했습니다. 개별 인증·동의·갱신 설정도 실행 범위에 포함합니다. 모든 제품 구현을 줄 단위로 리뷰하는 보안 감사나 실서버·Electron 기동 검증은 아닙니다.

1. 반복 실패를 재현한 뒤 준비 조건과 격리를 먼저 고칩니다.
2. 같은 시나리오를 불필요하게 여러 폭에서 반복하는 부분과 구현 모양만 고정하는 검사를 정리합니다.
3. 단위·린트·타입·실제 빌드, 화면·세션·OAuth 브라우저 검사를 순서대로 실행합니다.
4. 통합한 결과를 dev에 squash하고 main으로 푸시합니다.

## 확인한 원인과 변경 기준

- 가이드의 `networkidle`은 화면 준비를 뜻하지 않았습니다. 지속 연결과 자료 로딩에 막혀 정상 화면에서 시간 초과가 났습니다. 본문 조회 결과·검색 창·선택 상태를 기다리며, 키보드 검사는 실제 검색 창 왕복으로 핸들러 연결부터 확인합니다. 검색어로 직접 들어온 경우에는 본문 검색을 닫지 않습니다.
- dev 서버의 HMR이 여러 경로 컴파일 도중 문서를 재시작해 `ERR_ABORTED`와 실행 문맥 소실을 일으켰습니다. 기본 화면 검사는 최적화 빌드와 자체 서버를 사용합니다. 기존 서버를 재사용하지 않으며, API 주소·분석 수집 환경·로컬 팀 자료 여부는 테스트 설정에서 고정합니다. 개발자 자료나 실계정 API를 검사 대상으로 삼지 않습니다.
- 배포 빌드의 정상 링크 prefetch를 페이지 상태 변경으로 잘못 셌습니다. 현재 화면의 실제 RSC 내비게이션만 세며 다른 경로 미리 가져오기는 제외합니다. 요청 자체를 막아 오류를 숨기지는 않습니다.
- 스켈레톤은 임의 시간에 응답을 돌려주면 빠른/느린 머신에서 측정 시점이 달라졌습니다. 셸 부팅을 막지 않고 검사할 API만 보류해 측정한 뒤 직접 해제합니다. 전환 기하는 글꼴과 유한 애니메이션 종료 후 비교합니다.
- 이미지 확대 창을 닫을 때 긴 원본 버튼으로 포커스를 돌리면서 문서가 움직이는 실제 버그도 확인했습니다. 공통 확대 창에서 `preventScroll`로 포커스를 복원하고 기존 위치 검사는 유지합니다.
- PDF 생성 워커는 배포 시 파일명이 해시로 바뀝니다. 소스 파일명 대신 브라우저의 실제 워커 생성 이벤트를 관측하며, 다운로드·메일 첨부의 PDF 바이트와 캐시 재사용은 계속 확인합니다.
- 대화 동작을 화면 폭마다 반복할 필요는 없었습니다. 동작은 대표 폭에서 한 번, 패널 기하와 모바일 넘침은 필요한 폭에서 각각 확인합니다.
- 모든 가이드 페이지를 단일 테스트의 제한 시간 안에서 렌더하던 검사는 페이지별로 나눕니다. 원시 문서 조각을 다시 렌더하는 중복 검사는 제거하고, 실제 페이지·문안 검사는 유지합니다. 단위 검사 워커 수는 4개로 제한합니다.
- `line-break.test.ts`의 CSS·git grep과 proposals `scope.test.ts`의 식별자·훅 이름·필드 집합 고정은 동작 검증을 대신하지 못했습니다. 실제 줄바꿈 E2E와 proposals 계약·reducer·선택기·UI 검사는 유지하고 해당 파일은 제거했습니다. 디자인의 radius 클래스 금지·그림자 콤마 개수 검사도 제거하되 토큰 존재와 실제 색 대비 계산은 남깁니다.
- OpenAPI·AsyncAPI 정합성, nullable 목 표본, 인증·소켓·녹음의 실패 경계는 서로 다른 계층의 회귀를 잡으므로 삭제하지 않습니다.
- 린트가 Playwright 산출물을 읽다가 파일 삭제와 충돌했습니다. 테스트 산출물을 정적 검사에서 제외합니다.

## 실행 정책

명령과 설정의 원본은 `package.json`, `playwright*.config.ts`, `vitest.config.ts`, `CLAUDE.md`입니다. 화면 검사와 실제 HTTP 가짜 서버를 쓰는 인증 검사는 서로 대체하지 않습니다. 전체 브라우저 검사는 별도 설정 세 개를 순서대로 실행하고, 실패를 skip하거나 전역 retry로 통과시키지 않습니다.

참고: [Playwright 대기 권고](https://playwright.dev/docs/api/class-page#page-wait-for-load-state), [Next.js Playwright 가이드](https://nextjs.org/docs/app/guides/testing/playwright).
