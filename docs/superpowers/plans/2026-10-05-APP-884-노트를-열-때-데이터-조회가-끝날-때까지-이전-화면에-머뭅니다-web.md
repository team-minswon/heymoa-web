## 건드리는 것

- 노트 서버 page: 서버 API 조회 대신 경로와 최초 탭·뷰만 반환한다.
- workspace prefetch: 사용자가 없는 노트 prefetch를 제거한다.
- note-panel: 미확인 제목·요약 표시를 로딩으로 바꾸고 실패와 구분한다.
- 관련 주석·테스트: 최신 화면 동작을 유지하며 진입 회귀를 검사한다. 노트 상태 확정 전 근거 점프를 시작하지 않고 종료 아카이브까지 대상을 보존한다.

## 순서

### 1. 최신 dev에 진입과 로딩 변경 적용

보존한 수정에서 필요한 부분만 최신 파일에 적용한다. route 반환·노트 제목·요약 미확인 테스트를 실행한다. 이 단계 커밋을 revert하면 기존 진입으로 돌아간다.

### 2. 전체 검증과 리뷰

워크트리에 의존성을 준비한 뒤 단위 테스트·lint·타입 검사·빌드·E2E를 실행한다. Node의 실험적 webstorage 충돌은 테스트 실행 환경에서 비활성화한다. 과도한 병렬 실행으로 생기는 시간 초과는 worker 수를 줄여 전체 실행한다. 테스트 코드를 느슨하게 바꾸지 않는다.

`codex exec review --base origin/dev`를 실행한다. P1·P2를 수정하면 해당 검증과 리뷰를 다시 실행한다.

## 마지막 관문

최신 원격 dev를 기준으로 `pnpm test:run && pnpm verify`와 `pnpm test:e2e` 전체를 통과시킨다. 이 레포에는 PR·CI가 없으므로 이 검증과 codex 리뷰가 병합 관문이다. base가 바뀌면 재검증한다.

docs 설계를 main에 먼저 병합한 뒤 web을 dev에 squash하고 push한다. main은 dev로 fast-forward해 push한다. 원격 두 브랜치와 docs를 확인한 뒤 Linear를 Done으로 옮기고 워크트리를 정리한다.

## 안 하는 것

API·실시간 계약·워크스페이스 셸 조회·분석 처리 시간 변경은 하지 않는다. 운영 속도 수치는 배포 후 측정 대상이다.
