# APP-464 검토 화면 재구현 — 실제 계약 위, 요약 탭의 editorial 문법으로

첫 구현(`feat/app-464/proposal-review-commit-ui`, pro-34 `8e5ecdd`)은 web이 제안한 계약을
가정하고 카드·배지 문법으로 그렸다. 서버 계약(docs origin/main, APP-460 #73)은 검토본을
**항목 목록만**으로 정의하고, 관계·평가·승인 게이트는 그 응답에 없다. 승인(PR #74)은 AI 비교
결과를 되돌려 보내는 다른 모델이다. 그래서 버리고 다시 만든다.

## 원칙

- 계약이 있는 것만 만든다. 항목 조회·생성·수정·제외 세 경로다. 승인·관계·평가·개념 요약은
  public 계약이 docs origin/main에 올라올 때 붙인다.
- 화면은 기존 요약 탭(`SummarySections`)의 문법 그대로다 — 세리프 섹션 머리글과 개수,
  헤어라인 하나, 글줄 항목, 각주형 근거. 카드·배지·상시 버튼 없음.
- 서버 상태는 TanStack Query만 가진다. 편집은 완료 단위로 저장하고 응답을 캐시에 바로 쓴다.
  모듈 보관소·저장 큐·잠금 맵을 두지 않는다. 미저장 상태는 열린 편집기 하나뿐이다.
- 생성 훅(`lib/api/generated/meeting-review/`)을 직접 쓴다. 임시 어댑터 없음.

## 순서

1. 계약 미러 갱신 + `pnpm orval` (끝) — 45 → 48 경로
2. `lib/notes/meeting-review/select.ts` — 항목을 kind 순서로 묶기, 인용을 전사 줄로 풀기. vitest
3. `lib/mocks/meeting-review.ts` — 노트 `01K0000000020`(내가 시작, 전사 있음)·`…21`(남이 시작)
   시드, GET 404 / POST create / POST items / PATCH items, CAS 409, 시작자 아님 403.
   `handlers.ts`에 등록
4. `components/notes/meeting-review/` — `meeting-review.tsx`(조회·상태·툴바·섹션),
   `review-item.tsx`(글줄·각주 근거·인라인 편집·제외/복원). vitest
5. `note-summary.tsx`가 종료 회의에서 검토 화면을 본문으로, 구식 분석을 「이전 분석」으로
   접는다. `note-panel.tsx`가 `isStarter`를 내리고 summary 탭을 `keepMounted`로 둔다
6. e2e `meeting-review.spec.ts` — 섹션·근거 펼침·수정·제외·시작자 아님
7. 게이트 5종, codex 리뷰, docs spec 갱신과 이슈 ③ 댓글

## 안 하는 것

- 승인 버튼과 확정 뒤 화면. 계약(`POST /v1/notes/{noteId}/approval`)이 origin/main에 없고,
  요청 본문이 AI 비교 결과를 요구하는데 그 조회 public 경로가 없다
- 관계 목록·1-hop 연결 뷰·회의 평가·프로젝트 개념 요약 route. 같은 이유
- 재마운트 대응 보관소. summary 탭 `keepMounted` + 편집기 하나라 잃을 것이 없다
