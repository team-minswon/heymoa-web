관계의 백그라운드 재조회 안내 깜박임, 최신 flow 조회 실패를 대기로 표시하는 문제와 그래프 zoom의 렌더 중 상태 갱신 경고도 수정했습니다. nullable 표본 검사는 선택 필드의 생략만 null로 세고 필수 필드의 생략은 null 표본으로 세지 않습니다.

Mock의 새 APPLIED 허용은 실제 서버의 호환 처리와 같으므로 유지합니다. 새 AI 안건은 description 빈 배열을 사용하고 옛 결과는 설명 전문을 보존합니다. 안건 연결은 source=current, target=previous 계약이므로 그래프가 target에서 source로 향합니다. 알 수 없는 관계 종류는 유추하지 않습니다. NOT_REQUESTED의 안건 폴링은 자동 분석 진입·늦은 결과를 받기 위한 대기 상태 갱신으로 유지합니다. 미분류 새 명제 뒤에는 이전 안건이 계속 논의 중이라고 추정하지 않습니다.

전체 브라우저 테스트 114개를 한 번에 통과했습니다. 이후 보완에는 전체 단위 검사와 관련 브라우저 테스트 9개를 다시 통과했습니다. 중단한 Playwright 실행이 남긴 임시 trace가 ESLint에 잡힌 실행은 통과로 세지 않고, 완료 뒤 임시 산출물을 정리한 상태에서 verify를 다시 통과했습니다.

Codex 2차 검토에서 추가 결함이 없음을 확인했습니다. 최종 공개 Mock에서도 반영↔넘기기→검토 완료→반영됨까지 확인했고 대기·충돌 안내가 남지 않았습니다. 데스크톱·모바일 넘침은 없었고 브라우저 오류도 없었습니다. APP-1184의 최종 생성물과 검토 GET/추가/PATCH·승인 경로 및 관련 응답·요청·관계 스키마를 재대조해 일치함을 확인했습니다.

APP-1170은 사용자 요청으로 Canceled로 변경하고 전체 범위·완료 기준을 APP-1152로 옮겼습니다. 기존 PDF는 입력에 전문이 있어도 안건 표에서 짧게 줄이고 별도 본문을 싣지 않았습니다. 목차의 요지는 유지하되 안건별 전문을 별도 본문에 보존합니다. 긴 회의 정리와 안건·표를 쪽에 들어가는 조각으로 나누며 원문 내용은 생략하지 않습니다. 목차·안건 번호·녹취록의 본문 참조를 내부 링크로 연결하고 북마크를 제공합니다.

다운로드·메일 창은 사용자가 요청할 때만 실제 PDF 미리보기를 만듭니다. 동일 문서·옵션의 결과는 같은 회의 화면에서 재사용하고 내용·옵션 변경 시 이전 미리보기를 감춥니다. 문서 변경·닫기·언마운트 시 이전 생성 작업을 취소하고 워커와 Blob URL을 정리합니다. 생성 실패에도 입력을 유지하고 재시도하며 중복 생성·발송을 막습니다. 기존 메일 봉투 미리보기는 별도로 둡니다.

- [x] APP-1170 취소와 범위·관계 이전, docs spec checkpoint를 반영했습니다.

### PDF 출력 검증 표본

Linux 7.1.8 x86_64, Node 24.16.0, 저장소의 react-pdf 4.9.0과 한글 글꼴을 사용했습니다. 합성 회의 5/60/180분에 안건 2/8/8개와 6초 간격 발언 50/600/1800개를 넣었습니다. 3시간 표본은 긴 회의 정리와 안건별 90문장, 긴 한글·영문 담당 이름과 URL을 포함합니다. 아래 시간은 Node의 inline 렌더를 두 번 실행한 결과이며 브라우저 캐시 응답 시간은 아닙니다.

| 회의 길이 | 최초 / 반복 렌더 | 파일 크기 | 쪽수 |
|---|---|---|---|
| 5분 | 712 / 356ms | 106,219바이트 | 7 |
| 1시간 | 2,534 / 3,120ms | 213,047바이트 | 41 |
| 3시간 | 9,439 / 9,390ms | 436,500바이트 | 120 |

Poppler의 raw 텍스트와 원본 모델을 대조해 회의 정리·모든 안건 전문·결정·할 일·모든 발언의 존재를 확인했습니다. pypdf로 링크 8/32/32개가 실제 목적지 12/30/30개에 연결되는지, 북마크와 대상 쪽이 유효한지 확인했습니다. 모든 쪽의 텍스트 좌표와 단어 경계는 용지 안에 있으며 첫 쪽·안건 본문·녹취록 표 경계·마지막 쪽 PNG에서도 겹침을 발견하지 못했습니다. 브라우저에서는 녹취록 제외·포함 출력과 미리보기/다운로드/메일 첨부 바이트 일치, 워커 재사용, 옵션 변경 시 미리보기 숨김을 확인했습니다.

한 표에 1800발언을 넣으면 뒷부분이 쪽 밖에 그려지는 문제를 실제로 재현했습니다. PDF에서 텍스트를 추출하는 것만으로는 놓치므로 텍스트 좌표와 PNG를 함께 봤습니다. 표를 최대 100행씩 측정하도록 나눠 해결하고 긴 녹취록 페이지 회귀 검사를 추가했습니다. 표의 경계에는 칸 머리가 다시 표시됩니다. PDF 뷰어의 내부 표시를 지원하지 않는 기기에서는 같은 파일의 새 탭 링크를 사용할 수 있습니다.


미리보기 생성 중 수신자·메시지는 편집할 수 있고 발송 버튼은 생성 대기와 구별합니다. 모바일은 빈 iframe 영역 대신 실제 PDF를 새 탭으로 여는 링크를 제공합니다. 공개 Mock에서 데스크톱·390px 화면의 가로 넘침과 화면 밖 버튼이 없었고 미리보기·다운로드 바이트가 같으며 브라우저 오류가 없었습니다.

긴 PDF 회귀 검사는 병렬 부하에서 30초 제한을 넘는 경우를 확인해 내용·쪽수 검사를 유지하고 이 검사만 90초로 조정했습니다. 복구 실패 처리와 첫 조회 취소를 반영한 최종 전체 단위 검사는 53초에 모두 통과했습니다. 다른 긴 PDF 검증과 겹친 최초 E2E는 화자 지정의 초기 화면 5초 대기가 만료돼 114/115 통과했습니다. 해당 화자 테스트를 바꾸지 않고 전체 재실행에서 통과했습니다. 복구 실패 처리를 포함한 최종 전체 E2E 115개도 3.4분에 모두 통과했습니다.


충돌 복구는 저장 중 비활성화된 검토 쿼리도 `fetchQuery`로 직접 읽고 새 판을 받을 때까지 잠금을 유지합니다. 복구 조회가 실패하면 입력을 남기고 재시도를 안내하며 성공했다고 표시하지 않습니다. 업무 목록은 진입과 늦은 분석 결과 반영 때 다시 읽습니다. 기대 판보다 캐시 판이 낮으면 조회 중에 변경 충돌로 표시하거나 넘기기를 강요하지 않습니다. 느린 충돌 복구·실패 후 재시도·최근 캐시보다 높은 유효한 제안의 회귀 검사를 추가했습니다.


복구 조회 실패 뒤 자동 GET이 성공해도 다른 사람의 수정 안내와 작성 중인 내용을 남깁니다. 업무 판 재확인 실패는 낮은 캐시를 충돌로 판정하지 않고 행과 완료 막대에 실패·재시도를 표시합니다. 입력 폼의 PATCH 409→첫 GET 500→자동 GET 200, 업무 GET 실패→재시도→유효한 반영을 회귀 검사에 포함했습니다. 최종 관련 검사 70개, 전체 단위 2,603개·lint·타입 검사·build와 전체 브라우저 115개를 통과했습니다. 실제 서버 통합과 base 병합·배포는 별도입니다.


관계 대상 이동에는 실제 검토 행과 상세 패널만 스크롤 대상으로 표시합니다. 같은 항목 ID를 가진 그래프의 숨김 접근성 버튼을 선택하지 않습니다. 단위 검사에서 실제 패널의 `scrollIntoView` 호출을 확인했고, 공개 Mock 브라우저에서도 이슈 관계 대상 클릭→그래프 전환→실제 DIV 패널이 화면 안에 들어오는 것을 확인했습니다. 마지막 스크롤 보완 후 전체 단위 2,603개와 lint·타입·build, 관련 E2E 15개를 통과했습니다. 전체 E2E 115개는 직전 복구 실패 보완 코드에서 통과했으며, 마지막 보완의 영향 범위는 이 관련 묶음으로 다시 확인했습니다.


늦은 분석 완료 뒤 검토본·요약·스크립트·관계를 다시 읽을 때는 조회 실패가 resolve되는 기본 동작을 사용하지 않습니다. 필수 조회가 모두 성공한 경우에만 해당 흐름을 갱신 완료로 기록합니다. 실패하면 이전 내용과 초안을 보존하고 재시도 안내를 표시하며 검토 완료를 막습니다. 같은 흐름의 폴링은 실패를 지우지 않고, 새 흐름이나 사용자가 누른 재시도에서 다시 읽습니다. 업무 목록 실패는 기대 판과 캐시를 대조하는 기존 제안별 상태로 처리합니다.


연결 중단으로 멈춘 조회는 실제 자료를 받지 않고 resolve될 수 있으므로 필수 쿼리의 무효화가 해제됐는지도 확인합니다. 첫 응답을 기다리는 조회는 invalidate만으로 이전 요청이 취소되지 않아, 완료 신호 전에 시작한 요청을 취소하고 새 요청으로 읽습니다. 수정 전에는 새 요청이 없고 이전 응답을 기다리는 것을 재현했고, 수정 후에는 새 자료가 먼저 표시되며 늦은 이전 응답이 이를 덮지 않는 것을 확인했습니다. 새 분석 도착·재시도도 PDF 문서 판에 반영하고 최신 자료 조회가 끝나기 전이나 실패 중에는 오래된 PDF 생성·발송을 막습니다.


늦은 분석 자료 재조회와 PDF 갱신을 포함한 코드(a4a7e3d)의 전체 브라우저 115개는 3.4분에 통과했습니다. 이후 첫 조회 취소만 보완한 코드(5bca99f)는 전체 단위 2,607개와 lint·타입·build, 검토·실시간 안건·자동 추종·PDF·메일의 관련 브라우저 15개를 다시 통과했습니다. 최초 검토본이 지연되는 회귀 검사는 수정 전 요청 수가 1개로 남아 실패하며, 수정 후 새 요청의 최신 내용이 먼저 표시됩니다.


## 사용자 확인 후 PDF 보고서 서식 정정

사용자가 보고서에 앱의 분류·이동 요소를 넣은 점을 지적하셨습니다. PDF에서 제목 후보와 목차 복귀 문구, 본문 하이퍼링크를 제거했습니다. 목차는 실제 안건 제목을 싣고 안건별 논의 전문은 다음 절에서 읽습니다. 가짜 ‘기타’ 안건은 만들지 않으며 안건 미지정 결정·할 일·미결은 기존 상세에 보존하고 안건 번호를 ‘—’로 표시합니다. 주요 절·안건의 북마크는 유지합니다. 화면의 안건 이동 기능은 그대로 사용합니다. 위의 내부 링크 개수 측정은 이 정정 전 출력의 기록입니다.

수정 후 PDF 관련 31개 검사와 변경 파일 lint·타입 검사를 통과했습니다. 공개 Mock에서 다시 받은 PDF는 5쪽·134,381바이트이며 본문 링크 0개, 북마크 13개와 쪽 밖 텍스트 0개를 확인했습니다. 실제 첫 쪽과 안건 본문 PNG를 열어 밑줄·빈 분류·이동 문구가 없고 전문이 읽히는 것을 확인했습니다. 미리보기와 다운로드의 파일 바이트가 같고 데스크톱·모바일 가로 넘침과 브라우저 오류가 없었습니다.

사용자 추가 확인에 따라 ‘작성’ 행의 자동 작성 도구명·공유자 정보·부록 안내도 제거했습니다. 회의명·일시·참석자만 개요에 두고 확정 여부는 제목 아래 문서 상태로 표시합니다. PDF 렌더링 검사 6개와 변경 파일 lint를 통과했습니다.
