# APP-1152 최종 요약 Web 반영

- 설계: docs `docs/app-604/final-summary @ 3570618`의 APP-604 공통 spec.
- 서버: APP-1151 `5caa1905`, 계약 미러 `docs/app-1151/server-contract @ 33d9538`.
- 서버·AI가 아직 Draft이므로 Web 변경을 전용 브랜치에서 검증하고 배포 순서를 유지합니다.

1. 최종 요약의 public REST 응답을 대조하고 변경된 `ProjectMeetingLinksResponse`를 원본에서 복사한 뒤 Orval을 실행합니다. 최신 dev에 추가된 문의 API는 보존합니다.
2. 회의 개요는 lead를 우선하고 headline은 제목 후보로 구별합니다. 안건은 summary 전문을 사용하며 옛 응답만 description/sentences로 대체합니다. 화면·복사·PDF 입력을 일치시킵니다.
3. 관계의 출발/대상 참조와 판을 보존합니다. 충돌·대체·취소·해결·이어짐을 구별하고 같은 회의/이전 회의/승격 항목과 근거를 표시합니다. 안건 연결은 같은 회의와 이전 회의 모두 탐색합니다.
4. 요약이 먼저 오면 읽을 수 있게 하고 영역별 대기·실패·빈 성공을 구별합니다. 관계/담당 도착 시 캐시를 갱신하되 컴포넌트를 다시 마운트하거나 편집 중 저장 요청을 재조회로 덮지 않습니다.
5. 새/옛 응답 selector·컴포넌트 통합·MSW 브라우저 흐름을 검증하고 test:run, lint, typecheck, build, test:e2e를 실행합니다.

PDF 전문 보존·페이지 구성·미리보기는 APP-1170에서 다룹니다.


## 추가 확인과 수정

- 종료 응답 뒤 옛 flow GET을 취소하고 캐시를 무효화합니다. 요약 탭은 진입 시 최신 flow를 확인한 뒤 수동 분석 요청을 제공합니다.
- 새 A/B 배정에 맞춰 진행 문구와 영역별 폴링을 바꿉니다. 요약 후에도 관계·담당이 대기 중이면 검토 완료를 기다리고, 늦은 화자 결과도 다시 읽습니다.
- 사라진 안건 ID와 새로 소속이 생긴 미분류 항목은 정본으로 옮깁니다. 그룹 key는 전체 그룹 순번 대신 그 묶음의 첫 명제 ID를 사용합니다.
- 사용자가 안건·근거를 펼칠 때 자동 추종을 중지하고, 맨 아래로 이동하면 다시 추종합니다.
- 같은 회의 안건 연결과 이전 회의 안건 링크는 대상 안건을 펼치고 이동합니다. 관계는 정확한 끝점·판·종류·판정 이유와 원문 이동을 보여 줍니다.
- 기존 화자 선택 E2E는 APP-1168 이후 기본 후보 정책을 반영하지 않아 변경 전 dev `4dbb9f8`에서도 실패했습니다. 비참여 멤버를 검색한 뒤 지정하는 현재 흐름으로 테스트를 맞춥니다. 화자 후보 제품 코드는 바꾸지 않습니다.
