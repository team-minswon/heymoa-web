## [P2][blocking] 배포 중 PAUSED 상태의 호환성을 유지하세요

> web을 APP-218 서버보다 먼저 배포할 때 기존 서버가 `PAUSED`인 노트를 반환하면 문제가
> 생깁니다. 해당 노트를 새로고침하면 이 분기가 `ENDED`가 아닌 모든 런타임 값을 `active`로
> 처리해 공유 챗과 녹음 UI를 열지만, 기존 서버는 두 요청을 거절하고 재개 버튼도 제거되어
> 회의를 계속할 수 없습니다.

**수용. 다만 코드가 아니라 배포 순서를 고쳤습니다.**

지적이 정확합니다 — 그리고 **원인은 이 분기가 아니라 제가 정한 web-first 순서**입니다.
두 창을 비교하면 server-first가 명확히 덜 해롭습니다.

| | web 먼저 (원래 계획) | **server 먼저 (정정)** |
|---|---|---|
| 기존 `PAUSED` 노트 | **교착.** 배포 창 내내 못 쓴다 | **즉시 풀린다.** V16이 `IN_PROGRESS`로 되돌린다 |
| 새 `PAUSED` 행 | 구 web 탭이 계속 만들 수 있다 | 경로가 404라 **생길 수 없다** |
| 구 web의 손해 | — | 중지 버튼이 404 토스트 하나 |

`deriveMeetingPhase`에 `PAUSED` 관용 분기를 넣는 방법도 있었지만 **넣지 않았습니다.**
계약에서 사라진 값을 web이 다시 알게 되고, 그 분기가 언제 죽는지 아무도 기억하지 못합니다.
server-first면 web은 `PAUSED` 행이 없는 세상에만 배포됩니다.

`heymoa-server` 설계 문서의 "배포 순서" 절에 근거를 함께 적었습니다.
