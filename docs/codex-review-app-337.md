# APP-337 codex 리뷰 기록

`codex exec review --base dev` 4회차. P1은 없었고, **네 회차가 전부 같은 자리** —
「새 회의」 다이얼로그의 폼 제출 —를 파고들었다.

## 1회차

| 라벨 | 지적 | 처리 |
|---|---|---|
| P2 | 비동기 생성 완료까지 폼 제출을 유지하라 | 고침 — action을 `async`로 바꾸고 `await` |

함수형 form action은 **완료되면 비제어 입력을 비운다.** 기다리지 않으면 요청이 끝나기도 전에
지워져서, 실패했을 때 사용자가 쓴 이름이 사라진다.

## 2회차

| 라벨 | 지적 | 처리 |
|---|---|---|
| P2 | mutation 실패를 form action 안에서 처리하라 | 고침 — 입력을 controlled로 + `catch` |

1회차 수정이 새 문제를 만들었다. **React 19는 거절된 form action을 오류 경계로 올린다** —
생성이 4xx나 네트워크 오류로 실패하면 토스트가 뜬 뒤 워크스페이스 전체가 `app/error.tsx`
오류 화면으로 바뀐다.

삼키면 되는데, 삼키면 action이 성공으로 끝나 **1회차에서 지키려던 입력값이 또 비워진다.**
그래서 값을 컴포넌트가 들고 있게(controlled) 바꿨다. 그러면 action의 리셋 동작과 무관해진다.

## 3회차

| 라벨 | 지적 | 처리 |
|---|---|---|
| P2 | 생성 성공 시 입력값도 초기화하라 | 고침 — 성공 경로에서만 비움 |

2회차 수정이 또 새 문제를 만들었다. controlled로 바꾸니 부모가 `setNewMeetingOpen(false)`로
닫기만 해서, **다음에 열면 지난 회의 이름이 그대로 남았다.**

성공했을 때만 비운다 — 실패에서 비우면 1회차로 돌아간다.

## 4회차

| 라벨 | 지적 | 처리 |
|---|---|---|
| P2 | 실제 생성 성공 뒤에만 다이얼로그를 닫아라 | 고침 — 생성 성공 여부를 boolean으로 돌려줌 |
| P3 | 처리 중에는 닫기 X를 감춰라 | 고침 — `showCloseButton={!isPending}` |

첫 지적이 앞 세 회차의 뿌리였다. `createMeeting`이 `void`라 **대상 프로젝트가 없거나 응답
guard(`201 + success:false`)에 걸려 조기 반환해도 성공과 구분되지 않았다.** 노트도 라우팅도
없는데 창이 닫히고 입력까지 비워져, 사용자는 만들어진 줄 안다.

`Promise<boolean>`으로 바꿔 다이얼로그와 툴바가 같은 값으로 판정하게 했다.

## 남는 것

비제어 폼과 낙관적 리셋의 조합이 실제로 이 세 상태를 다 만든다.

| 상황 | 입력값 |
|---|---|
| 생성 중 | 유지 (action이 아직 안 끝남) |
| 실패(거절) | 유지 |
| 조기 반환(만들어지지 않음) | 유지 |
| 성공 | 비움 |

`workspace-sidebar`의 프로젝트 생성 다이얼로그도 같은 모양(`action={(formData) => void
handleProjectSubmit(formData)}`)이라 같은 셋을 밟을 수 있다. **이 작업에서 건드리지 않았다** —
범위 밖이고, 그쪽은 실패 경로를 직접 토스트로 처리하고 있어 증상이 다를 수 있다.
