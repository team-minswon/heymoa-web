# APP-187 codex 게이트 기록

`codex exec review --base feature/app-148-멤버-초대-이메일-발송-및-확대` (통합 브랜치 기준).
8회차, P2 총 8건 — 반영 6, 반려 2(같은 지적 3회 반복). 6·8회차 클린.

## 반영한 것

### R1-1. 목 초대 생성의 inviteeName을 null로 (db.ts)

목엔 가입자 레지스트리가 없는데 이메일 앞부분으로 이름을 지어내고 있었다 — 계약에 없는
값을 발명하는 쪽이라, 전부 미가입자 취급(null)이 더 정직하다. 덤으로 dev에서 초대를
만들면 이메일-주텍스트 폴백 UI가 바로 보인다.

### R2~R4. 만료 시계 삼부작 (db.ts)

APP-187이 UI 만료 판정을 실제 시계로 만들면서 목의 시계들이 연쇄로 어긋났다.

- **R2**: `nextExpiry()`가 목 시계(2026-07-12 고정)라 dev에서 새 초대가 즉시 "만료됨"으로
  보였다. codex 제안(mockNowMs 기준)은 오답 — 그래도 실제 시계엔 과거다. 실제 시계 기준
  생성+1일로 수정.
- **R3**: 이번엔 `expireIfNeeded()`가 목 시계와 비교하고 있었다. `mockNowMs` 자체를 삭제하고
  판정도 실제 시계로 통일. 시드 만료 시각이 전부 실제-상대(`daysAgoIso`)로 옮겨진 뒤라
  목 시계는 존재 이유가 없었다.
- **R4**: 생성 시각과 만료 시각을 같은 `Date.now()` 호출에서 계산하도록 마무리.

교훈: 한 화면이 시계를 바꾸면 그 데이터를 만드는 목의 시계 전부가 따라와야 한다.

### R5-2. 만료 409 후 재조회 (members-settings.tsx, notification-bell.tsx)

만료 행의 취소·수락은 서버가 409를 내면서 초대를 EXPIRED로 전이시킨다(APP-184,
noRollbackFor). 성공시에만 목록을 갱신하면 이미 목록에서 빠진 행이 화면에 남는다 —
취소는 `onSettled` 재조회로, 벨은 `INVITATION_EXPIRED` 오류 분기에서 재조회 추가.
브라우저에서 만료 행 취소 → 행 제거 실검증.

### R7-2. 계약 서술 갱신 (서버 → 미러)

계약의 초대 생성 설명이 "가입된 사용자를 초대한다"로 낡아 있었다 — APP-183에서 미가입자
초대를 정상 경로로 만들 때 문구를 안 고친 누락. 목을 되돌리는 게 아니라(실동작은 서버·목
일치) 서버 DocsTest 문구를 고치고(`6e5c9b1`, 서버 통합 브랜치) `clean openapi3` 재생성 →
웹 사본 갱신(diff 문구 한 줄) → orval 재생성.

## 반려한 것

### 만료 시각 실시간 갱신 (R1-2 → R5-1 → R7-1, 3회 반복)

"화면을 열어둔 채 만료 시각을 지나면 버튼·배지가 낡는다"는 지적. 이슈 스펙이 명시적으로
**"시간 비교는 렌더 시점 1회 고정 — hydration 불일치 방지"**로 정한 결정이라 반려.
그 좁은 창에서 버튼을 눌러도 서버 409 + 토스트가 안전망이고, R5-2 반영으로 409 후 화면
정리까지 된다. 타이머의 복잡도가 창의 가치보다 크다.
