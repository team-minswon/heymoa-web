# 사용 가이드 작성 안내

가이드(`/help/**`) 본문은 이 폴더의 마크다운이 원본이에요. 파일 하나가 페이지 하나예요.
`lib/help/content.ts` 가 빌드할 때 읽어서 라우트, 검색 색인, sitemap, JSON-LD(구조화 데이터)를 만들어요.
화면으로 바뀌는 모양은 `components/help/md/` 에 있어요. 아래 모든 표현을 한 화면에서 보려면 `/help-samples` 를 열어 보세요(검색에 안 잡히는 내부용 페이지).

## 파일 규칙

```
content/help/<그룹>/<slug>.md
```

- `<그룹>` 은 `start` `record` `summary` `team` `connect` `fix` `situations` 중 하나예요.
- 앞부분에 frontmatter(파일 맨 위 설정)를 꼭 적어요. 값은 한 줄이에요.

```
---
title: 처음 시작하기
description: 한두 문장. 40~120자. 해요체. 페이지 목록, 검색 결과, 공유 미리보기에 그대로 나와요.
group: start
slug: getting-started
order: 1
kind: facts
---
```

- `slug` 와 `group` 은 `app/(static)/help/_content/ids.ts` 와 같아야 해요. 주소가 바뀌면 옛 링크가 깨지니 바꾸지 않아요.
- `order` 는 그룹 안 순서예요. 그룹 순서는 `_content/groups.ts` 가 정해요.
- `kind: facts` 는 상황별 페이지 중 따라 하는 순서가 아니라 사실 목록일 때만 써요(이 경우 HowTo 구조화 데이터를 안 내요).
- `title` 은 `제목 · HeyMoa(헤이모아) 사용법` 이 60자를 넘지 않게 써요.

## 페이지 틀

`## 제목 {#섹션-id}` 로 섹션을 나눠요. **섹션 id 는 바깥 링크가 `#id` 로 오는 주소라서 바꾸지 않아요.** H2 아래에서만 H3(`###`)을 써요. 더 깊은 제목은 없어요.

```
## 이렇게 해요 {#steps}
```

권장 흐름은 이래요.

1. 맨 위는 `description` 이 요약이에요. 본문은 바로 시작해요.
2. 번호 단계: 무엇을 하는지.
3. 자주 막히는 점은 증상 / 원인 / 해결 방법.
4. 한도와 주의는 알림 한 개로 짧게.
5. 끝에 `## 자주 묻는 질문 {#faq}` 와 `## 관련 페이지 {#related}`.

## 표현 문법과 보이는 모양

| 쓰는 법 | 보이는 모양 |
|---|---|
| 번호 목록. 항목의 첫 `**굵은 문장**` 이 제목 | 단계 카드 (번호 원 + 굵은 제목 + 설명, 세로 연결선) |
| `> [!참고]` `> [!팁]` `> [!주의]` `> [!되돌릴 수 없어요]` | 아이콘 + 종류별 포인트 선이 있는 알림 |
| GFM 표. 칸에 `✓` `✗` `–` 만 쓰면 | 줄무늬 표, 해당 칸은 아이콘 칩 |
| `::::tabs` 안에 `:::tab{title="Mac"}` | 탭 (스크립트 없이도 모든 내용이 보여요) |
| `:::problem` 안에 `**증상:**` `**원인:**` `**해결 방법:**` | 3칸 블록 |
| `## 자주 묻는 질문 {#faq}` 아래 `### 질문?` 과 답 | 접이식 질문 (첫 질문만 열려 있어요) |
| `::clip{name="…" alt="…" caption="…"}` | 움직이는 설명 (영상 클립) |
| `![설명](img:주제/파일.webp "캡션")` | 눌러서 크게 보는 그림 |
| `==핵심 문구==` | 형광펜 (페이지당 2~3곳만) |
| `` `kbd:⌘K` `` | 키캡 |
| `` `코드` `` , 코드 블록 | 코드체, 코드 블록은 복사 버튼이 붙어요 |
| `:badge[관리자만]` | 작은 배지 |
| `[이름](help:slug#섹션-id)` | 가이드 안 링크 (주소는 자동으로 풀려요) |
| `[이름](/privacy)` , `[이름](https://…)` | 사이트 안 링크, 바깥 링크(새 탭) |
| `## 관련 페이지 {#related}` 아래 `- [제목](help:slug) — 한 줄 설명` | 링크 카드 묶음 |

### 단계

```
1. **[새 노트]를 눌러요**
   [새 회의 만들기] 창이 열려요.
2. **회의 이름을 정해요**
   오늘 날짜가 채워져 있어요. 그대로 써도 돼요.
```

한 단계에는 한 동작만 적어요. 제목은 굵은 한 줄, 설명은 1~2문장이에요. 상황별 페이지(`group: situations`)는 `{#steps}` 섹션의 번호 목록이 JSON-LD `HowTo` 가 돼요.

### 알림

```
> [!주의]
> 삭제하면 되돌릴 수 없어요.
```

- `참고` 덧붙이는 설명. `팁` 더 편한 방법. `주의` 조심할 일. `되돌릴 수 없어요` 한 번 하면 되돌릴 수 없는 일.
- 한 페이지에 알림이 많으면 안 읽혀요. 섹션마다 한 개까지만 써요.

### 탭

```
::::tabs
:::tab{title="Mac"}
Mac에서는 …
:::
:::tab{title="Windows"}
Windows에서는 …
:::
::::
```

바깥은 콜론 네 개, 안쪽 탭은 콜론 세 개예요.

### 증상 / 원인 / 해결 방법

```
:::problem
**증상:** “녹음을 시작하지 못했습니다”가 떠요
**원인:** 마이크 권한이 없을 수 있어요.
**해결 방법:** 브라우저 사이트 설정에서 마이크를 허용하세요.
:::
```

세 줄 사이는 빈 줄 없이 이어 써요. 해결 방법 아래에 목록을 이어도 돼요. 문제 해결 페이지는 이 블록이 FAQ 구조화 데이터가 돼요.

### 자주 묻는 질문

```
## 자주 묻는 질문 {#faq}

### 종료한 회의에 이어서 기록할 수 있나요?
아니요. 종료한 회의는 다시 기록할 수 없어요. 새 회의를 만드세요.
```

답은 `네,` 또는 `아니요.` 로 시작하는 짧은 글이에요. 3개 안팎으로 써요.

## 글 쓰는 법

말투는 담백하고 쉽게 써요. 다른 서비스 문서를 참고했지만 문장은 베끼지 않아요.

- **해요체** 로 통일해요(~해요, ~돼요, ~하세요). 합쇼체(~합니다, ~습니다)는 쓰지 않아요. 서비스가 주어이면 "헤이모아가 …" 라고 써도 돼요.
- 한 문장에는 한 가지만 담아요. 40자 안팎, 길어도 70자 아래예요. 한 문단은 3~4문장 안이에요.
- 제목은 사용자가 겪는 말이에요. "~하는 법", "~가 안 돼요", "~이 뭔가요?".
- 내부 용어(리스, 시드, run 등)를 쓰지 않아요. 어려운 말은 바로 풀이해요. 예) "워크스페이스(팀이 함께 쓰는 공간)".
- 영어와 약어(MCP, OAuth, PDF)는 처음 나올 때 한 줄로 풀이해요.
- 숫자는 단위와 같이 써요. 예) 1일(24시간).
- 한도와 예외는 별도의 짧은 문장이에요. "다만 …" 으로 시작하고 숫자를 바로 적어요. "할 수 없어요" 를 숨기지 말고 바로 뒤에 대안을 이어요. 예) "대신 …을 쓰세요."
- 목록은 "항목: 설명" 한 줄씩이에요.
- 한 페이지에 같은 말을 되풀이하지 않아요. 한도 숫자는 필요한 곳에 한 번만 적어요.

### 화면 이름과 따옴표

| 무엇 | 어떻게 | 예 |
|---|---|---|
| 화면에 보이는 버튼, 메뉴, 탭, 칸 이름 | 굵은 대괄호 | `**[새 노트]**` , 경로는 `**[설정]** → **[멤버]**` |
| 화면에 뜨는 문구, 사용자가 입력하는 예시 | 큰따옴표 | `“저장했어요”` , `“10/18 회의록”` |
| 코드, 값, 파일 형식, 주소 | 코드체 | `.pdf` , `?view=` |
| 단축키 | 키캡 | `` `kbd:⌘K` `` |

- 낫표(`「」` `『』`)는 쓰지 않아요.
- 눌러야 하는 것이 아닌 일반 개념어는 따옴표 없이 그냥 써요.
- 화살표 `→` 는 화면 이동 경로에만 써요.
- 화면 라벨은 실제 화면과 같게 써요. 코드에서 대조해요.
- 사실(숫자, 한도, 라벨)은 바꾸지 않아요. 확인하지 못한 것은 "아직 확인 중이에요" 로 적고 약속하지 않아요.

```bash
pnpm vitest run "app/(static)/help"   # 구조, 메타, 검색 색인

```
